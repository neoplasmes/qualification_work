# BI Tool - редизайн: задание для агента

Перенести новый дизайн в код веб-сервиса. Макеты лежат рядом в папке `qw_redesign/`, дизайн-система в `design-system/`.

## Что где лежит

| Путь | Что это | Как использовать |
|---|---|---|
| `design-system/README.md` | Брендбук: три шрифта, цвета, форма, ссылки, маркер | Прочитать первым. Правила обязательны. |
| `design-system/tokens.json` | Все токены: цвета, кегли, отступы, радиусы | Единственный источник значений. |
| `design-system/tokens.css` | Те же токены как CSS-переменные | Подключить глобально как есть. |
| `design-system/components/bundle.css` | Стили компонентов, классы `bt-*` | Эталон. Разнести по компонентам. |
| `design-system/components/<Имя>/README.md` | Правила каждого компонента | Читать перед реализацией компонента. |
| `qw_redesign/<Экран>/<Файл>.dc.html` | Разметка экрана | Структура, порядок блоков, тексты, классы. |
| `qw_redesign/<Экран>/*@2x.png` | Снимок экрана | Сверка результата на глаз. Значения из него не брать. |
| `qw_redesign/BI Tool - редизайн.pdf` | Все экраны одним файлом | Общий обзор. |

Не переносить в продукт: `support.js`, папку `vendor/`, теги `<x-dc>`, `<helmet>`, `<sc-for>`, `<sc-if>`, `<dc-import>` и блок `<script type="text/x-dc">`. Это движок макета, не код сервиса. Копии `ds/bt/` внутри каждой папки экрана одинаковые, брать одну из `design-system/`.

## Как читать .dc.html

- `{{имя}}` - подстановка значения из метода `renderVals()` внизу файла. Там же лежат данные списков и состояние.
- `<sc-for list="{{items}}" as="item">` - цикл по массиву, в продукте это `items.map(...)`.
- `<sc-if value="{{cond}}">` - условный рендер.
- `this.state` и `setState` в `renderVals()` - локальное состояние экрана. Интерактивен только экран «Действия - запуск»: счётчик, выбор канала, запуск и отмена.
- Инлайновые стили задают раскладку конкретного экрана. Стили компонентов живут в классах `bt-*`.

## Порядок работы

1. Подключить шрифты (ссылка на Google Fonts в `design-system/README.md`) и `tokens.css`.
2. Сделать базовые компоненты по `bundle.css` и их README: Link, Button, Choice, Field (с Stepper), Token, Marker, Table, Stat, Stamp, Nav, Sheet, Notice, Lead.
3. Собрать каркас: шапка `Nav` и строка заголовка экрана высотой 52px с чёрной линейкой снизу. Она одинаковая на всех экранах, вкладки не должны сдвигаться при переключении.
4. Переносить экраны по одному, сверяя со снимком.

## Правила, которые нельзя нарушать

- Цвета, кегли и отступы только из токенов. Своих значений не добавлять.
- Углы прямые везде, кроме мазка маркера, аватара и тумблера.
- Маркер `--marker` только для «изменилось», «выбрано», «под курсором». Текущий пункт меню и вкладка залиты `--ink`.
- Предупреждения: прозрачный фон, обводка и ярлык `--red-ink`. Заливки у них нет.
- Числа в таблицах: моноширинный шрифт, `tabular-nums`, выравнивание вправо.
- Любая цель нажатия не ниже 44px.

## Чего в макете нет

Это решить при реализации или спросить у меня:
- раскрытый список «Быстрые действия» на дашборде и окно предупреждения по значку;
- пустые состояния, ошибки загрузки, состояние загрузки;
- диалог «Несохранённые правки» при переключении действия;
- адаптив для экранов, кроме «Запуск с телефона».

## Данные в макете - заглушки

Не переносить в код как реальные: имена сотрудников, номера заказов, остаток 14 шт., часть значений на графиках, площадки в «Сравнении», раскладка тепловой карты, действия «Принять поставку на склад» и «Оформить возврат поставщику», содержимое шаблонов на стартовом экране.

## Новые механики, которых нет в бэкенде

Нужна отдельная задача на бэкенд, не только вёрстка:
- запуск действия из выбранной строки таблицы с подстановкой её значений в поля;
- пробный запуск действия без записи («Проверка на ваших данных»);
- защита «не давать остатку уйти в минус»;
- правила «требует внимания» (минимальный остаток);
- кто сейчас смотрит дашборд.
